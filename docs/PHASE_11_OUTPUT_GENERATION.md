## Artifact Storage

`output_generation.py` now provides:

- `OutputArtifactContent`
- `OutputArtifactStore`
- `InMemoryOutputArtifactStore`
- `AzureBlobOutputArtifactStore`
- `output_artifact_store_from_environment()`

Local/offline work defaults to `ORDER_PROCESSOR_OUTPUT_ARCHIVE_BACKEND=memory`. Deployed mode can use Blob Storage with `ORDER_PROCESSOR_OUTPUT_ARCHIVE_BACKEND=blob`.

Blob configuration:

- `ORDER_ARTIFACTS_STORAGE_ACCOUNT_URL`
- `BLOB_SERVICE_ENDPOINT`
- `STORAGE_ACCOUNT_NAME`
- `ORDER_ARTIFACTS_CONTAINER_NAME`, default `order-artifacts`

The Blob implementation uses managed identity through `DefaultAzureCredential`.

## Generated Artifacts

Every processed order now receives a stored `universalOrderJson` artifact.

If no output profile is configured, the backend also generates the default `lineCsv` artifact for continuity with the prior scaffold.

`orderRuns.outputArtifacts` now stores references instead of inline file content:

- `id`
- `type`
- `fileName`
- `contentType`
- `blobUrl`
- `sizeBytes`

## Output Profiles and Adapters

Supported profile types:

- `csv`
- `xlsx`
- `text`
- `api`
- `json`
- `multi`

Profile resolution order:

- inline `outputProfiles` in the process request
- `outputProfileId` or `outputProfileIds`
- `processorProfiles.outputProfileId`
- request-time `outputTypes` or `requestedOutputTypes`
- customer-scoped `outputProfiles`
- tenant-global `outputProfiles`
- default line CSV when none are configured

CSV settings support field selection, delimiter, header inclusion, encoding, and filename templates.

XLSX output is generated by backend code and stored as an Open XML workbook. No Plumsail connector is used.

Text output supports line templates such as:

```json
{
  "template": "{line_number}|{matched_internal_item_number}|{quantity}"
}
```

API output generates a stored API payload with method, URL, headers, and body. It is marked with `deliveryStatus: "pendingExternalDelivery"`; external delivery is left to a later backend worker or optional customer-specific M365 adapter.

## API Behavior

`POST /orders/{orderRunId}/process` now resolves output profiles, generates output payloads after final order status is known, stores artifacts, and writes artifact references back to `orderRuns`.

If output generation fails, the order is marked `failed`, an `outputGeneration` exception task is created, and the error is recorded in `order.errors`.

`order.processed` audit events now include output artifact count and output profile ids.
